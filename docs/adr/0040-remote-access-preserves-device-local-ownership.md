# Remote access preserves device-local ownership

Remote Access lets a user operate their own devices through the existing Reveric application while Works and agent execution remain on the accessed device. Devices are peers in the domain model: a phone or computer may serve either role, although the MVP supports Android accessing Windows or macOS only. Remote operations require the accessed device to be online; disconnection preserves unsent input rather than enabling offline workspace writes and later merging. This keeps remote access separate from cross-device data synchronization and avoids making computer ownership a permanent protocol assumption.

The product will provide a default hosted relay. Personal devices establish trust through QR pairing, with paired-device inspection and revocation, rather than account registration or automatic account-wide trust. The relay forwards end-to-end encrypted content without persisting business content. The accessing device keeps no offline Work replica; it may retain unsent input drafts, while temporary media files must be cleaned up when access ends. Explicit download or export is a separate action, not implicit synchronization.

Remote Access opens and continues the accessed device's existing agent sessions and can create sessions on that device. Messages, execution and approvals belong to those same sessions. In the MVP, people view Work content without directly editing it; they can send instructions, stop execution and approve or reject tool operations. Content changes run through the accessed device's existing Agent capabilities across Work types. Remote Access does not require every existing UI action to gain an Agent tool first. This avoids duplicating editing forms and save flows while preserving direct human control of execution.

The MVP reuses actual mobile views and adds the missing read-only presentation of the general Canvas and the production workspace, including production views, the editing timeline and the director view. People can pan, zoom, select, expand details, switch views and play media without editing Work content. Screenshots and summaries are not the default substitute for these views, and porting every desktop editing control is not a prerequisite. This expands the mobile presentation scope beyond a Canvas-only port; remote data subscriptions, resource access and action routing remain necessary even where a mobile view already exists.

Existing messaging integrations remain available as IM Channels, separately from Remote Access. ADR-0002's independent IM Assistant session model continues to describe those messaging integrations; it does not apply to Remote Access, which uses the accessed device's sessions.

Each device navigates independently. Remote instructions bind their target Work and applicable Season or Episode when sent rather than following the accessed device's current page; this preserves ADR-0030's device-local navigation boundary. Inputs to the same session share one pending-input slot across devices, with one active turn at a time. Both devices can see the pending input. Further input stays in the sender's draft with an explicit occupied-slot response, and only acknowledgment from the accessed device establishes that input is queued. A user can explicitly stop the current turn before changing direction. Different sessions can run independently.

Disconnecting or closing the accessing app does not stop work already running on the accessed device. Operations requiring human approval wait for a decision, and reconnection restores the authoritative execution and approval state. If the accessed device's app exits or restarts, the MVP reports interrupted work rather than automatically replaying unfinished mutations.

Pairing grants device-wide access to view all Works, direct the Agent and resolve approvals. Existing tool-permission rules still apply on the accessed device; remote origin does not automatically authorize an operation. The MVP has no remote controls for changing provider secrets, platform permissions or device-pairing settings. The accessed device shows active remote connections, can end them, and can revoke access.

The MVP provides live updates while the accessing app is connected in the foreground and reconciles state when it returns. It does not promise timely lock-screen notifications or introduce a separate background push service; tasks continue on the accessed device and pending approvals wait for the user to return.

Connection establishment prioritizes direct access on the local network and uses the selected WebSocket relay when local access is unavailable. The MVP supports the hosted Cloudflare relay and a self-hosted relay backend, without public-network P2P traversal or TURN. Mainland China and overseas networks are both target environments for acceptance; Cloudflare is not the only supported relay deployment.

Self-hosted mode is independent of official accounts, discovery and relay services, including pairing and cross-network connection establishment. The pairing QR carries the selected relay address and necessary device identity information. A failed self-hosted relay does not trigger an automatic switch to the official relay. Already-paired devices can connect directly on the local network while their relay is unavailable. Both relay implementations use the same client protocol and application distribution; users configure an endpoint rather than install a deployment-specific client.

Video is read like every other remote resource: the accessing device requests byte ranges of the accessed device's file through the end-to-end encrypted channel, directly on the LAN or through the selected relay across networks. The relay forwards ciphertext without caching or persisting it, and no copy is uploaded to object storage. Revocation ends active reads immediately, although bytes already buffered by the player cannot be recalled. Playback throughput across networks is bounded by flow-control windows and relay bandwidth; the MVP accepts this limit rather than requiring users to configure storage, and an on-demand lower-bitrate preview can be added later if measurements show it is needed.
