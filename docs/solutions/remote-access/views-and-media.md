# 移动视图与媒体访问

> 返回[方案总览](README.md)。任务状态只在总览的[实施任务](README.md#实施任务)维护。

## 平台展示差距

| 区域 | 已有移动能力 | 本方案工作 |
| --- | --- | --- |
| 小说与剧本文本、人物、设定、大纲、场景 | 有 | 复用真实展示组件，接远程数据并关闭内容修改入口 |
| 地图、实体关系图、当前进展 | 有 | 保留缩放、筛选、选择；详情进入只读模式 |
| Agent 聊天、工具卡、提问与审批 | 有共享基础 | 显示和操作指向被访问端的同一个会话 |
| 普通画布 | 无移动入口 | 复用画布绘制与查看模式，增加移动宿主和触摸详情 |
| 制片节点画布、素材网格 | 无完整移动入口 | 移植真实只读展示，保留节点选择与结果查看 |
| 剪辑时间线、导演台 | 无移动入口，部分底层已共享 | 移植查看、播放和视图切换，不移植全部编辑控件 |
| 制片音视频预览 | 缺对应完整移动入口 | 应用内播放、拖动进度与全屏，接远程资源读取 |

工作量不只是移动端补一个画布：制作画布与普通画布是两套实现，移动端能显示分镜数量也不等于已有制作工作区。已有视图照常展示，不降级为截图或 Agent 总结。

## 用户流程与信息归属

### 配对与访问

1. Windows 或 macOS 设置新增“远程访问”，用户开启后选择官方中转或自建中转地址；IM Channels 保持独立设置区域。
2. 电脑显示限时二维码。Android 从“连接设备”扫码，显示目标设备名称和确认状态；电脑确认手机加入。
3. 配对后，手机优先连接局域网地址，不可达才连接该配对关联的 Relay。两端都显示实际路径和目标设备。
4. 手机进入该设备的作品列表。进入作品后保留已有分区结构，只读查看内容、媒体及复杂视图，打开既有会话或新建会话。
5. 用户发送指令后，被访问端回复已启动、已排队或拒收原因。未得到确认时显示“正在确认接收状态”，不提示成功，也不生成新命令重发。
6. 返回本机或切换设备时，在内存中保留按设备和会话隔离的未发送输入，释放当前远程订阅、媒体资源和临时文件。已在对端执行的任务继续。

官方中转地址由发行配置提供，自建地址由用户配置。更换 Relay 按重新配对处理，不从旧 Relay 迁移作品或会话，也不自动覆盖已有设备记录。

两端都可以中止访问，效果不同：

- **被访问端断开**：设置页和窗口内常驻的状态标识显示当前活动的远程连接（设备名称、路径、开始时间），可一键断开。断开只结束本次连接，配对保留，对方可以重新连接。
- **被访问端撤销**：让该设备的凭据立即失效，需要重新配对才能再访问。
- **访问端断开或移除**：只影响访问端本地的连接和设备记录。

### 状态归属

| 内容 | 权威来源 | 访问端持有方式 |
| --- | --- | --- |
| 作品内容、媒体与 Agent 历史 | 被访问端现有数据库和文件 | 内存视图快照、按需读取的媒体 |
| 活动回合、待发送输入、审批、AskUser | 被访问端的会话服务与运行态 | 订阅镜像，决策提交回被访问端 |
| 当前浏览分区、选中对象、缩放与播放进度 | 每个访问端自己 | 页面局部状态，不改变另一端导航 |
| 未发送输入 | 输入所在设备 | 访问端内存中的输入框内容，按设备与会话隔离，不持久化，不混入本地作品会话 |
| 配对身份、信任记录、中转配置 | 各设备自身 | 私钥和凭据放系统安全存储，非敏感配置放本地设置 |
| 在线路由、连接额度 | 所选 Relay | 仅通信元数据，不含作品和会话正文 |

复用视图时，数据来源、资源来源和动作来源三者都要切换到远端。远端的 `databasePath` 不能当成本机路径用，也不为迎合现有 Provider 把整个远程数据库复制到手机。

## 资源、媒体与临时数据

### 资源读取

一次资源读取的过程：

1. Host 根据业务资源引用解析本地文件，验证归属和可读权限后打开句柄，返回不可变的版本标识。
2. 之后每次读取都带上这个版本。素材被替换或删除时，Host 结束旧读取并报告 `resource_changed`。
3. 访问端重新打开资源，不把两个版本的字节拼在一起。

访问端只能按资源引用请求，不能直接请求磁盘路径、任意 URL 或遍历目录。

图片、音频、视频和其他文件统一经 `media.open/read/close` 读取，同网走局域网直连，跨网走所选 Relay，全程处于端到端加密通道内。图片、小文本按需读取；长正文和大列表分页。每次读取默认 256 KiB，再由安全通道分成[运行参数初值](connection.md#运行参数初值)规定的加密片。中止预览、切换设备或撤销权限时取消未完成读取。

### 视频经加密通道按范围读取

视频不另设传输路径，也不上传到对象存储。播放器每次拖动进度都对应一次新的范围读取（HTTP Range，按字节区间读取文件的一段），Host 只读请求的字节，不预先传输整个文件，也不发送自定义的“视频帧”消息。视频按原文件格式传输；MP4 内的编码不一定都能被目标设备解码。

| 路径 | 视频字节路径 |
| --- | --- |
| 同一局域网 | 局域网 WebSocket 上的加密 `media.read` |
| 跨网络 | 所选 Relay 转发的加密 `media.read`；Relay 只转发密文，不缓存、不落盘 |

吞吐上限约为流控窗口除以往返时延，并受 Relay 出口带宽限制；窗口初值见[流控与存活](wire-protocol.md#流控与存活)。播放期间按播放位置顺序预取，默认最多 4 个并行块；控制、审批和取消消息优先于媒体块进入有序写入器，视频读取不会把它们堵住。

经 Relay 播放原画质出现卡顿时，后续可由 Host 使用桌面端已有的 FFmpegKit 按需生成低码率预览并放入临时目录，再以同样方式读取；是否启用按实网测量结果决定，不在首版预先转码所有视频。

### 播放器适配

访问端提供仅监听 loopback（本机回环地址 `127.0.0.1`，其他设备访问不到）的标准 HTTP 适配器，播放器以 `http://127.0.0.1:<port>/<token>` 打开资源。适配器处理 `HEAD` 与带 `Range` 的 `GET`，返回 `200`、`206`、`Content-Range`、`Content-Length`、`Accept-Ranges`、MIME 与合法的 `416`，并把每个范围请求转换为对应版本的 `media.read`。

适配器只服务当前打开的资源，令牌随资源关闭失效，不代理任意 URL。媒体响应按流转发，不缓存整个文件，默认内存缓存 16 MiB。音频与视频共用这个适配器。loopback 明文只在本机进程间传输，平台网络策略只对 `127.0.0.1` 放行，TLS 和证书校验在其他地址上照常生效。

撤销设备会立即关闭控制连接与资源句柄，未完成的读取随之终止；已经下载到播放器缓冲中的字节无法收回。

### 为什么首版不用 WebRTC、HLS 或对象存储

按范围读取适合查看已经生成的视频文件，另外三种方式各有不适合的地方：

- **WebRTC**：适合低延迟的摄像头、屏幕或实时画面，需要会话协商、ICE，可能还要 TURN。
- **HLS**：需要生成播放列表与分段，多码率还要转码。
- **对象存储**：用户要额外配置，首次播放前要等上传完，云端还会留下未加密副本。

以后确实需要长视频自适应码率或实时画面时，再分别评估。

参考：[RFC 9110 Range](https://www.rfc-editor.org/rfc/rfc9110.html#name-range)、[WebRTC](https://developer.mozilla.org/en-US/docs/Web/API/WebRTC_API)、[HLS](https://www.rfc-editor.org/rfc/rfc8216.html)。

### 缓存与草稿

正文、会话快照、图片解码缓存优先放内存。确需临时文件的查看器使用 App 私有临时目录，按访问会话的随机 ID 隔离；无论成功、失败、取消、切换设备还是退出远程工作区，都会释放。程序崩溃遗留的远程临时目录在下次启动、展示远程内容前清理，只清理本功能创建的数据。

用户主动下载或导出是独立操作，通过明确入口交给系统保存机制，与缓存无关，也不在后台把媒体归档为本机素材。MVP 不新增批量同步或自动导出入口。

未发送输入保留在访问端内存中的输入框状态里，按设备、作品、会话隔离，清空时机见[命令确认](protocol.md#命令确认去重与单槽队列)；不持久化，不携带作品快照、远程图片缓存或供应商秘密。

### 聊天输入附件

远程输入沿用现有聊天支持的附件类型与模型能力检查。手机通过系统选择器读取文件，不把 `content://` 或本机路径直接发给 Host。上传分四步：

1. `input.open` 创建绑定设备和目标会话的临时句柄。
2. `input.write` 按偏移写入数据块，重复块会被识别。
3. `input.commit` 校验总长度与 SHA-256，返回附件 ID。
4. `session.send` 引用该 ID，Host 只接受已提交且归属正确的附件。

上传暂存只是发送前的准备，与被访问端作品里的文件是两回事。消息被接收前取消，本次暂存会被清理；接收后，附件按现有会话文件规则保存到被访问端。队列满时本端草稿保留；已提交但没有被任何输入引用的临时附件，10 分钟租约到期后清理。断线后只有原上传身份能恢复或查询这次上传，不会重复导入成两个资源。

单附件上限取被访问端原有输入限制与协议协商上限的较小值；协议初值为 256 MiB。超过时明确拒绝，不压缩或截断。资源只能落入会话暂存区，不接受客户端指定写入路径。

## 插件视图与只读边界

插件工具继续在被访问端运行。只读 A2UI 工具卡传模板和结果数据，由手机共享 renderer 展示，手机无需安装插件；资源引用转换为远程读取句柄。

已有插件页面包含 A2UI 和 TSX，不能当作静态卡片处理。远程页面实例在被访问端打开，JS 运行时也留在被访问端；节点树快照和增量经类型化 UI 消息传给手机，手机只用宿主组件渲染，不加载远端 JS。实例按配对设备和页面 ID 隔离，断线后关闭，再次进入重新取得快照。

浏览交互只能改变该页面实例的局部状态或执行只读查询。远程页面上下文由 Host 统一拦截业务写入、供应商配置修改、任意网络副作用和直接启动任务，不靠手机隐藏按钮。需要发起 Agent 操作的控件改走显式的聊天发送流程。插件若初始化时必须写入才能显示，就返回具体的不支持原因，不改用带写权限的普通页面实例。TSX 运行时及组件协议沿用现有插件系统，不另建 HTML/WebView 引擎。
