# 验收与交付

> 返回[方案总览](README.md)。任务状态只在总览的[实施任务](README.md#实施任务)维护。

本篇是实施后的验收合同。

## 前置工程验收

[P0 业务切片 PoC](application-decoupling.md#p0业务切片-poc) 按其完成标准验收，记录大画布单帧字节数与刷新耗时；P0 的明文传输只用于 Debug 验证，不能作为下述任何连接、授权或加密场景的通过证据。

依赖业务契约的远程任务（T05～T09）以[应用架构解耦的 T0 完成标准](application-decoupling.md#t0-完成标准)为前置门槛，包含改造范围内全部业务模块的契约替换、编解码器往返夹具、唯一写入语义、页面无关任务、来源隔离和三平台本机回归。T0 测试装配可模拟延迟与失败，但不能代替下述真实网络、授权和媒体验收；T0 未完成时不得将这些任务标记为进入实施。T01～T04 可并行实施，但其验收仍按下文执行。

## 连接与授权

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| A01 | 扫码、确认、重连 | 一次邀请只授权被确认的设备<br>重复确认不创建两个配对<br>过期或伪造邀请拒绝<br>Relay 不可达时可在局域网完成配对，Relay 恢复后该设备无需重新配对即可经 Relay 连接 |
| A02 | 同网访问 | 优先使用局域网<br>固定对端身份<br>关闭官方和自建 Relay 后，已配对设备仍能连接 |
| A03 | 局域网不可达 | 有限探测后走已选择 Relay，显示真实路径；不因同名 DNS-SD 服务信任陌生公钥 |
| A04 | 自建独立运行 | 阻断官方域名后仍能首次配对、发现和跨网连接；自建故障不自动请求官方中转 |
| A05 | 撤销与身份变化 | 撤销后控制连接及资源句柄立即失效，新命令和新读取拒收<br>被撤销设备在 Relay 加入即被拒绝、已有 channel 被关闭，其他已配对设备无需重新配对<br>Relay 不可达时撤销仍生效并在重连后同步<br>密钥变化要求重新配对 |
| A06 | 加密与重放 | 中转抓包只见协议必要元数据和密文；篡改、重复或错序帧关闭通道，不能明文降级 |
| A07 | 限额与慢连接 | 过大消息、连接额度、慢接收方产生明确结果<br>局域网与 Relay 两条路径下发送缓冲都受信用窗口约束，不随输入无限增长<br>局域网监听器拒绝路由帧、超时未握手和超额的未认证连接 |
| A08 | 版本与能力 | 主版本不符拒绝<br>可选能力缺失有明确说明<br>未知写方法不能进入任意业务分发 |
| A09 | 活动连接可见 | 访问端连上后，被访问端在设置页和状态标识中实时显示该连接及其路径；一键断开立即关闭控制连接与资源读取，配对保留，对方可重新连接 |

## 会话控制

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| B01 | 手机继续电脑会话 | 两端显示相同会话 ID、消息和工具结果；发送不创建独立 IM 助手或本机作品 |
| B02 | 不打开聊天页运行 | 正常交互式 runner 存活；关闭页面或手机断线不触发 headless 自动回答 |
| B03 | 同时发送与队列已满 | 同一会话只有一个活动回合和一个待发送位置；后来输入留草稿且收到占用结果 |
| B04 | 接收确认丢失 | 使用原命令 ID 查询<br>同参重试不重复执行，不同参同 ID 拒绝<br>未知结果不伪装为失败重发 |
| B05 | 租约到期与重启 | 过期租约的命令不被接收<br>同代次租约内查无回执返回未接收，其余返回未知<br>Host 重启后未确认命令显示结果不确定且不重放，新代次拒收旧租约写命令，并允许核对已有历史 |
| B06 | 停止与清空队列 | 区分取消请求和执行结束<br>不声称回滚已发生副作用<br>两种操作都由原输入端恢复待发送内容到输入框 |
| B07 | 双端审批 | 当前冻结参数只获一次决策，迟到端刷新为已处理；客户端自带参数无法替换执行输入 |
| B08 | AskUser 断线与超时 | 真实注册 PendingAskUser<br>30 分钟截止照常生效<br>旧 instanceId 或超时回答不作用于新请求 |
| B09 | 导航变化 | 手机和电脑独立导航；发送上下文固定，删除目标后拒收，不跳到另一端当前对象 |
| B10 | 快照与增量竞争 | 初始化期间发生变化不丢失；缺号、重复、重连和缓冲溢出后状态与 Host 一致 |
| B11 | 原有工具权限 | 未批准操作仍等待；远程来源不放宽权限，拒绝结果返回原执行链 |

使用确定性的假模型和可观测计数工具验证“实际执行次数”，不要只断言发送了几条网络消息。AskUser 使用受控时钟，禁止真实等待 30 分钟。跨重启未知结果测试必须包含外部副作用已发生而回执尚未送达的窗口。

## 媒体与存储

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| D01 | 远端图片与音视频 | 不直接打开电脑路径<br>Android 实机经 ExoPlayer 可播放应用导出的 H.264/AAC 与代表性 AI 生成视频，支持拖动和全屏<br>单独音频可播放<br>失败区分离线、版本变化和不支持的编码 |
| D02 | Range 与大文件 | loopback 适配器对首段、中段、尾段、越界范围返回正确的 `206`/`416`<br>HEAD 返回正确长度与类型<br>拖动无需下载完整文件，缓冲遵守上限 |
| D03 | 传输途中替换文件 | 版本失效并重新打开，不拼接新旧文件；切网恢复仍核对资源版本 |
| D04 | 退出、撤销、崩溃 | 释放 loopback 句柄和资源读取，临时文件按策略清理，重启清理只涉及本功能临时目录 |
| D05 | 输入附件 | 系统 URI 正确读取<br>重复块不重复导入<br>取消、队列满、半上传、散列不符均有明确行为 |
| D06 | 存储归属 | 访问端无远端作品数据库副本<br>Relay 不持久保存业务内容<br>密钥不随作品备份导出<br>新增表从受支持正式版直接升级的 migration 回归通过<br>Android 从自动备份恢复到新手机后，已配对设备显示需要重新配对且不自动连接 |
| D07 | 视频路径与吞吐 | 局域网与经 Relay 均可播放和拖动<br>记录两种路径下首帧、拖动耗时与持续码率<br>视频播放期间审批、停止等控制操作仍及时响应<br>版本变化与撤销立即终止读取 |
| D08 | 播放依赖边界 | Android 构建只引入 `video_player_android`，不含 fvp 与 FFmpeg<br>桌面播放与 FFmpegKit 导出回归不受影响<br>Release APK 体积增量记录在案<br>网络安全配置只放行 `127.0.0.1` |

媒体测试至少包含短片、512 MiB 级长文件、含中文名称的文件和设备不支持的编码。记录传输缓冲、解码器占用与进程总内存，分别判断，不把原生解码器正常内存当作网络缓存失控。只测当前播放器可支持的真实容器和编码，不承诺所有文件可播。

## 跨平台与网络矩阵

| 被访问端 | 访问端 | 必测路径 |
| --- | --- | --- |
| Windows Debug 与 Release | Android 真机 | 同网 LAN、禁组播后 Relay、防火墙拒绝、官方与自建 |
| macOS Debug 与 Release | Android 真机 | LAN 监听权限、Keychain、官方与自建、休眠后唤醒 |
| Windows 与 macOS | Android 真机 | Wi-Fi 切蜂窝、切回 Wi-Fi、锁屏返回、杀掉访问端、杀掉被访问端 |

大陆和海外各自覆盖局域网、官方 Relay、自建 Relay；视频分别记录局域网与 Relay 路径的播放表现，不能把 Relay 可达当作视频流畅；另测跨区域访问。记录运营商、网络类型、部署区域、实际路径、握手耗时、首屏耗时、媒体首帧和跳转耗时、断线恢复及失败原因。没有真实样本时标记未验证，不据地域标签假定可达或不可达。

本方案没有已测延迟基线，不编造成功率或速度承诺。协议超时是失败处理预算，不是产品性能达标线；发布评审使用实际样本对比同文件本机播放与局域网播放，明确哪些环境仍不能完成核心流程。

## 验证入口

协议生成验收执行 Buf lint、breaking 和 generate，核对生成目录无差异。Dart、Go、TypeScript 对同一批消息交叉编解码并比较语义，覆盖 optional、64 位整数、未知字段和 oneof；同一组黑盒客户端分别连接 CF workerd 和 Go 服务，验证窗口、断连和 Host 替换。

新增测试放在 `test/shared/services/remote_access/`、`test/mobile/features/remote_access/` 及各受影响业务目录。协议黄金夹具共用于 Dart 与 Relay，覆盖帧边界、静态 schema、Noise 握手和错误语义。

以下命令供实现完成后执行。新增目录、Relay 脚本随实现交付。Flutter 命令使用 FVM，所有测试串行运行，Widget 测试加外部超时：

```bash
timeout 180s fvm flutter test test/shared/services/remote_access --concurrency=1
timeout 180s fvm flutter test test/mobile/features/remote_access --concurrency=1
timeout 180s fvm flutter test test/shared/services/ai/chat_session_controller_handoff_test.dart test/shared/services/ai/pending_ask_user_test.dart test/shared/services/ai/tools_ask_user_test.dart --concurrency=1
timeout 180s fvm flutter test test/shared/widgets/ai/tool_approval_card_test.dart test/shared/services/remote --concurrency=1
fvm flutter analyze lib/shared/services/remote_access lib/shared/providers/remote_access_providers.dart
go -C server/relay vet ./...
go -C server/relay test -race ./...
npm --prefix server/cf/workers/relay run check
npm --prefix server/cf/workers/relay test
```

此外，在相应宿主平台运行 `fvm flutter build windows`、`fvm flutter build macos` 和 `fvm flutter build apk`，并执行各实际改动目录的最窄回归测试。构建成功不能替代真机和网络矩阵。生成源变化使用 `make codegen`，检查非目标生成文件没有被删除。真实本地化资源测试在 `setUp` 清理 `rootBundle` 缓存。

本方案不改 Prompt 或模型决策策略，不需要新增模型质量评分体系。用确定性模型验证传输与生命周期；真实供应商只做经授权的代表性小样本，记录模型、工具副作用和实际用量。不能为验收自动启动真实付费视频生成。

## 发布门槛

发布前应具备：Dart、Go、TypeScript 编解码互通及两种 Relay 的同合同测试记录、三平台 Release 实机记录、地域矩阵、故障注入记录、升级与关闭回归，以及官方实际中转地址。任何一项缺失都记录具体未覆盖项，不能用本机模拟器成功替代。

先部署能兼容当前协议的 Relay，再发布 App。Relay 更新应允许旧连接平稳断开后重连；不要同时切换协议主版本和全部部署。上线后按[运行观察](settings-and-deployment.md#上线观察与业务判断)复核。出现数据串设备、重复执行、越权或密文内容落盘时停止接入并修复；回退时保留作品和既有会话，不删除业务数据。
