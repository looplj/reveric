# 连接、配对与安全通道

> 返回[方案总览](README.md)。任务状态只在总览的[实施任务](README.md#实施任务)维护。

## 设备身份和配对

设备首次启用远程访问时，生成一个稳定的随机 `deviceId` 和一对 Noise 身份密钥。`deviceId` 只用来标识设备，不是授权凭据；信任关系以对方的公钥为准，配对时固定下来。身份密钥缺失、发生变化或系统安全存储读不出来时，停止自动连接并要求重新配对；Relay 声称某台同名设备换了密钥，一律不接受。

配对二维码包含：

- 协议版本、被访问端 ID 和公钥；
- 限时邀请 ID 和 256 位随机配对秘密；
- 所选 Relay 地址和邀请路由凭据；
- 局域网候选地址。

配对秘密和 Relay 路由凭据用途不同，必须分开：配对秘密只在建立好的加密通道里发给被访问端，路由凭据则交给 Relay 用来确认路由。二维码不含供应商密钥、作品路径或会话内容。

邀请默认 5 分钟有效，只能成功使用一次。配对流程：

1. 手机扫码，用二维码里的公钥与电脑完成 Noise 握手，确认对方就是这台电脑。
2. 握手后手机只能调用 `pair.claim`，提交配对秘密；在电脑确认之前，这条连接不能查询作品，也不能调用其他业务方法。
3. 电脑核对秘密、期限，并等待用户在电脑上确认，然后一次性消费邀请，保存手机公钥。
4. 电脑下发长期连接配置。

配对响应在途中丢失时，已确认的同一台手机可以查询这次配对的结果；其他设备不会因此获得授权。

配对邀请和日常连接使用不同的 Relay 路由。长期路由的注册凭据（owner token）只由被访问端持有；每台访问端在配对成功时拿到自己独立的加入凭据（join token），彼此不共享。两种凭据都是独立的高熵随机秘密。Relay 只保存加入凭据的 SHA-256 摘要（digest），被访问端提交给 Relay 的 digest 集合就是该路由的准入名单。

Relay 可达时，被访问端先把新手机的 digest 加进 Relay 上的准入名单并收到确认，再经加密通道下发加入凭据。

Relay 不可达时，仍可在局域网完成配对：二维码照常带上所选 Relay 地址和局域网候选，只是不含邀请路由凭据；配对经局域网完成后照常下发加入凭据，在此之前这台访问端只能走局域网。被访问端每次注册都提交全部未撤销设备的 digest 集合，下次注册成功时就会补上这台设备，不需要另外记录待同步状态。

Relay 放行一条连接只说明路由凭据有效；应用层是否授权，最终由被访问端核对固定公钥和配对状态决定。

撤销一台设备分三步：

1. 被访问端把该设备的信任记录标为已撤销并写入数据库，此后它的命令一律拒收，即使后面两步失败也是如此。
2. 断开它当前的连接和资源读取。
3. 向 Relay 提交去掉该设备 digest 的准入名单，让它连 Relay 名额都占不到。Relay 暂时不可达时，下次注册会提交最新名单。

撤销不会回滚已经执行的操作；正在等这台设备回答的审批或提问，在被访问端本机照样可以处理。

## 局域网优先与切换

开启接入的设备监听一个随机可用端口，并通过 DNS-SD 发布服务。访问端只探测三类地址：已配对设备的发现结果、最近成功连接过的地址、二维码里的候选地址，不扫描整个网段。发现结果本身不可信，连上后必须用固定公钥验证身份。局域网连接与 Relay 使用同一套分帧和信用窗口，建链方式和未认证连接的限额见[局域网链路](wire-protocol.md#局域网链路)。

连接时先试局域网候选，默认探测 2 秒；连不上再走这次配对关联的 Relay。2 秒是可调的工程初值。局域网握手发现对方身份不符时，记录失败并丢弃该候选。

已配对设备用本地信任记录完成认证，不向官方服务查询登录态。网络隔离了 DNS-SD 时，可以尝试已知地址或用户手工填写的地址；仍然不通就走所选 Relay。自建 Relay 不可用时明确报错，不会悄悄切换到官方 Relay。

已建立的连接保持稳定，不会每发现一个新地址就切换一次。网络变化或当前路径失效后才重新选路，新建加密通道和连接代次，并重新订阅快照。业务命令按原命令 ID 核对结果，不因换路径而重新执行；媒体按同一资源版本继续读取。

## 会话加密与协议协商

Noise 握手的 prologue（双方在握手前约定、参与认证的上下文数据）绑定应用协议版本、连接随机数和双方设备 ID，并区分首次配对和日常连接两种用途。业务内容只在握手完成且授权通过后发送，不在握手阶段夹带业务数据。

每个方向各自按顺序计数，连接恢复时重新握手、生成新密钥。认证失败、重放、计数错序或解密失败都会关闭当前通道，不会退回明文。局域网可以用 `ws://` 承载加密帧，公网必须用 `wss://`。Relay 不持有设备的解密密钥，也不做解密；加密发生在哪一层、字节格式如何，见[线协议](wire-protocol.md)。

双方协商 `protocolMajor`、`protocolMinor`、能力集和消息尺寸上限。主版本不兼容时拒绝连接并提示升级；缺少可选能力时，明确禁用对应入口。未知的写命令直接拒绝，不尝试改用自然语言或任意工具调用来完成。

## 运行参数初值

| 参数 | 初值与语义 |
| --- | --- |
| 连接与握手 | 局域网探测 2 秒；安全握手 10 秒；重连指数退避 0.5 秒至 30 秒，加入随机抖动 |
| 存活检查 | 每 30 秒探测一次，连续 3 次无回应判为失联；App 回到前台时立即探测，不等后台计时器 |
| 加密分片 | 每片明文最多 48 KiB；单个结构化消息最多 4 MiB；大列表分页，大媒体走流式读取 |
| 并发限制 | 每连接最多 128 个未完成的 RPC；资源读取按播放需要调度，默认最多 4 个块并行 |
| 背压 | 每连接发送队列上限 4 MiB；超限时暂停媒体读取，控制消息照常处理 |
| UI 订阅 | 只订阅当前设备、作品和可见区域；聊天增量批量刷新，不按 token 写数据库，也不重建整个页面 |

这些参数集中定义在协议配置里，两种 Relay 使用相同默认值。超过上限时返回可诊断的错误或暂停发送，不无限缓存，也不悄悄截断业务结果。
