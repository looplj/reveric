# 设置、部署与运行成本

> 返回[方案总览](README.md)。任务状态只在总览的[实施任务](README.md#实施任务)维护。

## 本地存储与升级

按数据性质分别存放：单值配置放 `app_settings`，有独立生命周期、需要按行查询和更新的记录建表，秘密放系统安全存储。MVP 不新增作品表或复制作品库，访问端不保存远端作品数据。

### 配置与秘密

| 位置 | 内容 |
| --- | --- |
| `app_settings` 键 `remote_access.settings.v1` | 接入开关、所选 Relay（官方或自建地址）、本机显示名称、局域网发现开关；被访问端另存长期路由的 routeId |
| `app_settings` 键 `remote_access.identity.v1` | 本机远程访问 `deviceId` 与公钥；与私钥同时生成 |
| 系统安全存储命名空间 `remote_access` | 本机身份私钥、被访问端的 owner 凭据、访问端按被访问端分别保存的 join 凭据、可选自建注册密钥 |

远程访问的 `deviceId` 独立生成，不复用匿名上报使用的 `DeviceIdService`，避免把匿名统计标识暴露给对端或 Relay。私钥写入成功后才保存身份元数据；两者不一致时关闭访问并提示修复，不回退到明文存储。

配置、身份和配对记录不随作品导出或备份复制到另一设备。

Android 未关闭自动备份，主库和 `app_settings` 会随备份恢复到新手机，Keystore 保护的安全存储则不会，结果是身份元数据还在、私钥已经丢失。处理方式：

- 访问端重新生成身份，把 `remote_access_hosts` 中的设备全部置 `revoked_at`，在设备列表中说明需要重新配对，不自动尝试连接。
- 被访问端从备份恢复时按身份变化处理，所有访问端都要重新配对。

### 新增表

两张表都放在主库 `AppDatabase`，记录已配对设备，供设置页列出和逐条撤销。跨库或跨表引用只存 ID 文本，不建外键；时间列按项目规则使用 `dateTime()`，`revoked_at`、`deleted_at` 沿用既有 `NOT NULL DEFAULT 0` 写法；公钥与摘要以无填充 Base64URL 文本存储；JSON 列使用 `type_converters.dart` 中的 TypeConverter。

**`remote_access_clients`：允许访问本机的设备（被访问端）**

| 列 | 类型 | 说明 |
| --- | --- | --- |
| `device_id` | TEXT，主键 | 访问端设备 ID |
| `display_name` | TEXT，默认空 | 配对时的设备名称 |
| `platform` | TEXT，可空 | 展示用平台标识 |
| `public_key` | TEXT | 固定的 Noise 静态公钥 |
| `join_digest` | TEXT | 该设备 join 凭据的 SHA-256 摘要（digest）；所有未撤销行的摘要就是提交给 Relay 的准入集合 |
| `paired_at` | INTEGER | 本次配对确认时间 |
| `last_seen_at` | INTEGER，可空 | 最近一次完成授权的时间 |
| `revoked_at` | INTEGER，默认 0 | 撤销时间；非 0 即不再接受该设备 |
| `created_at` / `updated_at` | INTEGER | 既有时间戳写法 |

撤销只更新 `revoked_at`，记录保留供设置页展示。同一设备重新配对时更新原行的公钥、join digest 与 `paired_at`，并将 `revoked_at` 置回 0。32 台上限只计未撤销的行，已撤销的行保留但不占名额；表规模很小，不建额外索引。

**`remote_access_hosts`：本机可以访问的设备（访问端）**

| 列 | 类型 | 说明 |
| --- | --- | --- |
| `device_id` | TEXT，主键 | 被访问端 ID |
| `display_name` | TEXT，默认空 | 被访问端名称 |
| `public_key` | TEXT | 二维码中固定的被访问端公钥 |
| `relay_url` | TEXT | 配对时选定的 Relay 地址 |
| `route_id` | TEXT | 长期路由 ID |
| `lan_candidates` | TEXT，`StringListConverter` | 二维码候选与最近成功的局域网地址，按最近成功排序，有上限 |
| `paired_at` | INTEGER | 配对完成时间 |
| `last_connected_at` | INTEGER，可空 | 最近一次连接成功时间 |
| `revoked_at` | INTEGER，默认 0 | 收到 `peer_revoked` 或身份不符时置位，停止自动重连 |
| `created_at` / `updated_at` / `deleted_at` | INTEGER | 用户在本机移除设备时软删除 |

用户移除设备时软删除该行，同时删除安全存储中对应的 join 凭据。凭据是连接秘密，不是业务数据，留着会让已移除的设备仍能连接。之后再次扫码配对同一台设备时恢复原行（`deleted_at`、`revoked_at` 置回 0），更新公钥、Relay、路由和候选地址，不插入新行。

### 只在内存中的状态

命令回执与租约、订阅、输入附件暂存句柄、媒体读取句柄和远程视图快照随连接或进程结束释放，不落库。未发送输入就是访问端聊天输入框的内容，与本机聊天一致，不另建草稿存储；App 被系统结束时未发送的文字随之丢失。输入附件的暂存文件放在被访问端的临时目录，按[聊天输入附件](views-and-media.md#聊天输入附件)的租约清理。

### 迁移

两张新增表需要提升主库 `schemaVersion` 并编写 migration。实施前按最新正式发布 tag 核对当前 schema 是否已发布，再决定合并进现有 migration 还是新增版本，并补齐从受支持正式版直接升级的回归测试。撤销和移除设备都是状态更新或软删除，本方案不新增硬删除。设置键不存在时远程接入默认关闭，已有 IM 设置保持原样。

## Relay 部署合同

CF 采用 TypeScript Worker 与 SQLite-backed Durable Objects（DO，Cloudflare 按 ID 定位的有状态单实例对象），自建采用 Go 单实例服务与 Caddy。共同二进制合同、注册认证、Host 替换、期限、关闭码与流控以[线协议](wire-protocol.md)为唯一来源。

[CF DO 分篇](cloudflare-relay.md)规定 Worker 如何在升级前定位 DO、持久化记录和连接附件、休眠恢复、alarm 清理、Wrangler 配置、平台限流和部署顺序。[Go 自建分篇](self-hosted-relay.md)规定连接并发、注册表文件、锁和原子替换、进程恢复、Compose/Caddy、就绪检查与优雅退出。两种实现共用 schema 和测试场景，运行时各自实现。

Relay 只持久保存路由验证元数据，不保存作品、会话或媒体，也不持有设备解密密钥。自建的注册表和 CF 的 DO 存储保存的内容相同；部署级限制按各自平台设置，Go 的进程级连接上限与 CF 的限额粒度不同。

部署所需外部资源只有 Cloudflare 账户及部署 API token，或自建服务器、域名和 TLS 证书。Cloudflare token 只在部署环境使用，不进入 App。MVP 不需要 TURN 凭据、推送账户、统一登录提供方或额外 AI API key。上线前由部署者提供实际地址，并执行健康、互通和故障验收。

## 平台验收前提

- **macOS**：当前 Debug/Profile 有 `network.server`，Release 没有。局域网监听要在 Release 构建上检查实际行为和所需权限；密钥存储要检查签名与 Keychain 配置。
- **Windows**：覆盖防火墙拒绝、网络从公用切到私用、mDNS 不可用。
- **Android**：按目标 SDK 检查相机、局域网发现和组播的实际要求。ExoPlayer 要访问 loopback（仅本机 `127.0.0.1` 可访问）播放适配器，网络安全配置只对 `127.0.0.1` 放行明文，不全局放宽。

MVP 不强行阻止电脑休眠，也不启动系统级常驻后台服务。操作系统休眠或网络被阻断时显示设备不可达，唤醒后重连；“手机退出任务继续”以被访问端进程仍可运行为前提。

## 运行成本

价格核对日期为 2026-11-02，以下仅用于选型，实际付费前重新核对官方价格。Workers/DO、TURN、Tunnel 是三种产品，计费方式各不相同。

| 成本项 | 当前口径 | 对本方案的影响 |
| --- | --- | --- |
| Workers Paid | 每月 5 美元起，包含请求和 CPU 额度；不另收带宽和出站流量费 | 官方 Relay 的基础费用，超额计算仍计费 |
| Durable Objects | 每月含 100 万请求、40 万 GB-s；超额每百万请求 0.15 美元、每百万 GB-s 12.50 美元 | 按活跃时间与消息计费，符合休眠条件时不计时长 |
| DO WebSocket | 入站消息 20 条折算一个计费请求，出站消息不收请求费 | 分块数量、心跳处理、活跃请求保持时间决定账单 |
| 自建 Relay | 服务器租金、实际运营商流量和出口费用 | 不套用 CF 价格；本地网络直连不经过该服务 |
| 客户端与被访问端 | 网络传输、加解密、缓存、解码与局域网监听 | 视频主要消耗在字节吞吐和解码；不默认转码 |
| AI 与工具供应商 | 按被访问端既有配置计费 | 远程访问不增加一个转述 Agent；重新下载结果不应再次调用生成模型 |

官方来源：[Workers](https://developers.cloudflare.com/workers/platform/pricing/)、[Durable Objects](https://developers.cloudflare.com/durable-objects/platform/pricing/)、[WebSocket Hibernation](https://developers.cloudflare.com/durable-objects/best-practices/websockets/)。本方案不使用 TURN；若未来增加，当前 [Realtime 定价](https://developers.cloudflare.com/realtime/sfu/platform/pricing/)为每月共享 1,000 GB 免费额度，之后每 GB 0.05 美元。Tunnel 也有独立的[隧道容量价格](https://developers.cloudflare.com/tunnel/features/tunnels-for-platforms/)，不是 DO 计费。

估算例子（按当前计费）：

- **空闲连接**：假设 1,000 个 DO 每天各有 10 分钟可计费活跃时间，其余时间休眠，每个实例按 0.128 GB、每月 30 天计算，共 2,304,000 GB-s。扣除包含额度并向上取整，时长超额约 25 美元，另加基础费及实际请求、CPU、存储费用。这只是时长模型，不是按用户数的报价。
- **视频**：跨网视频经 DO 转发，播放期间 DO 保持活跃。播放 10 分钟约 77 GB-s；1 GiB 视频按 64 KiB 帧约 1.6 万条入站消息，折合约 800 次计费请求，出站消息不计请求费。
- **会话流**：token 增量按 100 ms 合并后，一次持续 3 分钟的回复约 1,800 条入站消息，折合约 90 次计费请求，DO 活跃约 23 GB-s。不合并、逐 token 发送时，消息数会高一个数量级。

DO 的持久存储只放路由元数据；Relay 转发包括视频在内的密文，但不缓存、不落盘。每个连接的帧与缓冲上限见[运行参数](connection.md#运行参数初值)，部署再限制总连接与注册速率。过载时明确拒收或暂停生产，不无限排队。

## 上线观察与业务判断

不新建账号体系、转化埋点或后台报表。初期使用受控验收样本、客户端诊断和中转自身用量，统计范围与覆盖限制随结果一起记录。Relay 只处理密文，没有业务正文需要脱敏，因此不新增日志脱敏系统；保留连接、错误、时长、字节和资源占用等正常运行诊断。

| 要回答的问题 | 统计口径 | 来源与查看时机 | 判断后的行动 |
| --- | --- | --- | --- |
| 配对与连接是否可完成 | 成功建立授权通道的尝试数 / 明确发起的尝试数；按平台和路径分组 | 实网验收记录，首轮试用后及连接问题复现时 | 区分邀请、身份、发现、TLS、Relay 和 Host 离线失败 |
| 指令是否可靠到达 | 已确认接收、明确拒收、未知结果分别计数；按 commandId 去重 | 两端运行日志与会话记录，对报告样本核对 | 重复执行或误报成功立即修复，未知结果不能算生成失败 |
| 只读视图是否足以检查结果 | 代表任务能否定位实际修改记录或播放实际产物 | 按正文、关系图、画布、制片、剪辑、导演场景人工走查 | 修复缺失跳转、数据来源或资源访问，不用摘要掩盖缺口 |
| Relay 成本是否可接受 | 控制与媒体路径字节数、DO 请求与活跃时长；按路由的当日转发字节与连接时长 | 测试负载后与首个账期，区分 LAN 和 Relay；上线后按日查看路由用量汇总和账户用量通知 | 检查休眠失效、重复下载和背压；对异常路由按[用量监控与成本控制](cloudflare-relay.md#用量监控与成本控制)封禁或限额 |

当前没有发布基线，不预设成功率或延迟门槛，匿名设备数也不代表用户留存。官方中转看不到端到端的业务结果，网络请求成功不等于作品修改成功。样本不足时如实写明无法下结论，不为此扩建采集系统。

## 升级、关闭与回退

应用更新保留既有 IM、作品和会话数据。首次升级默认关闭设备接入，开启后才生成身份和监听服务。更换中转、身份丢失或重新配对均不迁移作品。

关闭远程接入时停止新连接、撤下发现广播、关闭远程订阅与资源读取；已经接收的 Agent 任务仍按会话规则执行，本机可以继续查看和停止；关闭网络功能不等于取消任务。

需要停用远程访问时优先关闭接入开关；远程设置键、新增表和安全存储记录保留，不删除业务数据，再次启用时重新校验身份。新增表提升了主库 `schemaVersion`，回退到不含这些表的旧应用版本按项目既有的数据库版本策略处理，不为此新增降级迁移。Relay 回退后必须仍支持已发布的协议；主版本不兼容时直接报错，不退回明文或弱认证连接。
