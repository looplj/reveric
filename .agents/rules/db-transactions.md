# 数据库死锁预防

- **检查事务里的完整调用链。** 沿 `await`、DAO 回调和 Service 调用确认实际访问的数据库，跨库读取也算。持有应用库事务等待作品库，同时另一条路径持有同一作品库事务等待应用库，会形成循环等待。
- **优先移出可提前完成的操作。** 先读取命名用的片段标题等独立数据，再开启写事务。文件审批、下载和媒体处理也尽量在事务前完成。同库的状态检查和依赖该检查的写入放在同一事务里。
- **需要同时访问多个库时，所有相关路径使用同一获取顺序。** 核对提交、取消、恢复和回调是否会反向获取数据库，或等待需要当前事务先结束的操作。拆分已有事务时，核对原有的更新顺序和重试行为。
- **WAL 下同一个 SQLite 文件仍然一次只有一个写事务。** WAL 允许读事务与写事务并行。应用层的循环等待要通过调整事务边界或获取顺序解除。
- **用受控并发测试验证修复。** 用 `Completer` 等同步点让相关路径在容易互相等待的位置交错，验证读取、写入和最终持久化状态。
