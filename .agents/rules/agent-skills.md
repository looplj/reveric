# 应用内技能的划分与维护

适用于 `assets/bundled_skills/`、`assets/official_skills/` 及其注册、加载和调用入口；不适用于供代码开发使用的 `.agents/skills/`。

**业务决定 Skill 入口，功能决定附件，基础性决定 bundled / official 归属。**

## Skill 边界与触发

- 按用户要完成的完整业务任务划分 Skill，不按 Read / Write / Run 等工具名称或界面容器划分。导演台人物、机位和时间轴属于剧本制片业务，不因显示在画布节点中就归入构思画布。
- `when_to_use` 写清用户意图、操作对象和任务阶段，并说明容易混淆的相邻任务边界。例如“正文完成或返工后的事实整理”归故事连续性维护，“讨论尚未发生的剧情”不触发事实写入。
- 不为减少 Skill 数量，把不同业务入口合成一个泛化的“工具使用”Skill。多个任务调用同一个工具，不是合并它们的理由。
- 同一业务所必需的方法与操作可以共存。不要为“工具说明／创作方法”的形式分离，拆散开书、制片或写后事实维护等完整流程。
- 技能的触发词、任务分段标题和反馈用语对齐实际 UI 名称；涉及内部资源名时明确映射。例如区分界面“分镜”、提示词中的 Shot 镜头和剪辑时间线的片段，不能用“分段”等自造名称替代。修改前核对桌面／移动端入口与翻译资源。
- 名称描述实际职责；“指南”“规范”等后缀不决定内容归属，也不能代替清晰的触发边界。

新增独立 Skill 前必须判断：用户是否会独立提出该任务、它是否有可区分的触发条件、拆分是否能减少无关加载并保留完整流程。仅是已有任务的一个步骤或场景时，优先放进现有 Skill 的附件。

## Bundled 与 official

| 归属 | 判断标准 | 内容边界 |
| --- | --- | --- |
| `assets/bundled_skills/` | 应用默认提供、随应用维护的基础业务入口 | 可以同时包含完成任务必需的方法、操作契约和按需附件 |
| `assets/official_skills/` | 用户可选择、替换和定制的专业方法 | 补充写作、设计、分析或制作方法，不承担应用基本操作的唯一契约 |

- 创作向导、故事连续性维护、画布构图、媒体处理与剪辑保留为 bundled 业务入口；不因它们包含方法内容就迁入 official。
- 故事连续性维护保留正文事实提取、实体状态、关系、伏笔及 `story_state` 维护的完整入口，不拆散到泛化的“资料管理”中。
- 官方技能可以调用基础操作；操作契约由对应 bundled Skill 或工具 schema 维护，不复制进各个官方技能。
- 归属不能仅按是否打包在应用内、是否自动安装判断。官方技能的安装、停用、删除与自定义选择必须被尊重，不能假定每次调用时必然可用。

## 附件与内容归属

- 主文件保留任务目标、边界、必要的共同原则和附件路由；按业务内的功能或场景拆分 `references/`，执行对应环节前按需读取，不预读全部附件。
- 一个任务涉及多个 Skill 时按职责引用。业务流程可以说明何时执行操作，但同一条操作契约只保留一处完整定义，其他位置给出加载入口或简短提醒。
- 创作输出格式归对应创作方法，例如 Shot 格式归剧本制片，剪辑操作流程归媒体处理与剪辑；不要放进工具 description、参数 description 或纯工具操作说明。
- 调用所需的 JSON 结构、字段类型、枚举与校验约束属于操作契约。参数定义遵循 `.agents/rules/ai-calling.md`，不要在 Skill 中重复抄写 schema 已有的整套字段说明。
- 内置技能之间共用操作说明时使用 `<inline-ref type="reference" skill="调用名" section="二级标题">references/附件.md</inline-ref>` 按小节引用，不复制正文；被引用小节保持作品类型中性，引用不得嵌套。
- 跨 Skill 引用不得形成互相要求先完整加载对方的循环。基础工具操作不能依赖可选官方技能才能理解调用契约。

## 打包官方技能按发布状态维护版本

- **打包官方技能按发布状态维护版本**：修改技能主文件或 references 附件前，先核对本地最新正式发布 tag 及其对应代码中的技能版本，不能仅凭当前分支、源码注释或版本号判断。当前技能版本已发布时，修改内容必须递增 `version`；经核实尚未发布时，将修改合并到当前版本，保持 `version` 不变。两种情况都同步更新 `contentHash` 和 `updatedAt`；hash 测试只校验内容一致性，不能证明是否需要升版本。保持版本号的开发修改不会触发已安装技能的自动升级，必须使用 SQLite skill 同步更新 Debug 数据库中该技能的官方安装快照、附件及相关内容指纹，并查询验证；没有安装记录时说明无需更新，不为此新增安装。保留安装 ID、启用状态、排序和历史记录，不覆盖已转本地或用户自定义的技能，不改 Release 数据库，也不为开发数据新增运行时兼容层。具体版本的发布状态只记录在本次核查结果中，不写入源码注释。

## 新增与调整时的检查

1. 先读相邻技能、附件及调用方，确认已有入口是否能承载任务，再决定新增 Skill、扩展附件或迁移内容。说明选择 bundled / official 的业务理由。
2. 用典型请求核对预期路由：应触发的任务、不应触发的相邻任务、需要多个附件或 Skill 的混合任务。静态文案检查不能声称已验证模型的实际触发准确率。
3. 同步检查注册表、资源声明、Run 命令到 Skill 的映射、Agent 提示词及桌面／移动端入口。改名或迁移时排查旧名称与附件路径，保留用户同名覆盖、停用和删除的既有语义。
4. 官方技能的版本、`contentHash`、`updatedAt` 及开发安装快照按本文件「打包官方技能按发布状态维护版本」处理；修改工具 description 遵循 `.agents/rules/ai-calling.md` 的明确确认要求。
5. 按 `.agents/rules/testing.md` 运行受影响的加载、附件、路由及官方内容指纹测试。仅修改本规则时检查文档 diff 与引用即可，不为文字规则新增 Flutter 测试。

主要维护入口：

- `lib/shared/services/bundled_control_skills.dart`：bundled 注册、命令映射与附件清单。
- `lib/shared/services/bundled_official_skills.dart`：official 注册、附件及版本元数据。
- `lib/shared/services/ai/chat_turn_runner.dart`：可用技能摘要、加载与同名覆盖。
- `lib/shared/services/official_skill_sync.dart`：官方技能安装与升级语义。
- `test/shared/services/bundled_control_skills_test.dart`、`test/shared/services/bundled_official_skills_test.dart`：资源加载与内容校验。
