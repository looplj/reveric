# 剧本写作

帮助作者完成改编方案、分集大纲、场次正文、对白或审稿意见。先确认这次要交付哪一种，再进入对应任务；已有方案直接沿用，局部改稿只处理相关上下文。

## 开始前

读取本次指定的材料、当前稿件及必要前后文。确认哪些是原文事实、哪些是已定改法，保留人物的目标、知情范围与前后行动。材料不全时说明缺口，不用旧梗概或记忆代替正文。

方向足够就开始写。缺口会改变主角、核心关系、结局或改编范围时，先与用户确认；普通措辞与局部节奏自行处理。固定集数与集长按分集任务确认，探索性讨论不必先问齐制作参数。

## 选择任务

| 用户要做什么 | 读取 | 交付什么 |
|---|---|---|
| 判断材料能否改编，或决定怎么改 | [改编](references/adaptation.md) | 有原文依据的判断与具体取舍 |
| 拆集、调整一集内容或重排多集 | [分集](references/episode-planning.md) | 每集的行动、结果与衔接 |
| 写一场、续写或修改场次正文 | [场次写作](references/scene-writing.md) | 可表演的动作与对白正文 |
| 改对白、区分人物声音、去掉解释腔 | [对白修订](references/dialogue.md) | 修改后的对话及必要动作 |
| 查问题或按问题审改 | [剧本审稿](references/review.md) | 有位置、依据和修订方向的问题 |

先读对应的一份任务附件，方法、难点与示例都在该附件内；时长估算仅在有相关要求时追加读取，不把整个目录当成必经流程。混合任务按交付顺序衔接，例如“改成两集并写第一场”先分集，再写指定场次。

附件通过 `<skill_resources>` 提供的 `reference-list` / `reference-get` 读取，`name` 为「剧本写作」，`path` 使用返回的附件路径。已读且仍在上下文中的内容无需重读。

## 共同的交付要求

- 写作任务先给成稿，分析只解释必要取舍；审稿任务先给问题，未经要求不直接改正文。普通写作做必要自检即可，不自动追加整套审稿报告。
- 有目标时长时，规划阶段给内容预算，正文完成后按 [时长估算](references/duration-estimation.md) 检查。计划、粗估和实测分别说明。
- 正文的路径、字段和元素结构由「剧本工具使用规范」维护，下文简称「工具技能」。正式写入前加载其剧本结构与正文附件，按它规定的结构落笔；写入后回读目标内容，保留已有身份和未改内容。当前作品没有该技能时只交付文本，不创建资源。小说对白修订保留小说叙述格式。
- 分镜、参考图与视频提示词交给「剧本制片」；写后事实整理沿用主 Agent 与「故事连续性维护」的流程。写剧本本身不触发图片、配音或视频生成。
