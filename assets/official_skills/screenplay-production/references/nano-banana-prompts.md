# Nano Banana / Gemini 图像提示词

用于 Nano Banana / Gemini 图像的生成与编辑。

## 用画面关系组织生成

用连贯自然语言描述用途、主体、动作状态、场景、构图与视觉表现。复杂画面可按背景、主体、细节逐层说明，各层必须在同一静帧成立；无需因元素较多就强行改成 JSON。

摄影镜头说明机位、景别、透视与景深；插画说明线条、色块、表面与层次。空场直接写清物理陈设与光线状态（如清晨未营业、桌椅收齐的茶馆），不堆叠「无人／无字」等排除词。

无参考的茶馆空场示例：

```text
清晨尚未营业的茶馆空场参考图，木桌与长凳收齐。从入口朝里平视，窄长房间尽头是柜台，左墙两扇高窗，右墙木架摆着茶罐。
中央通道贯通入口与柜台，靠左窗留一张两人方桌。柔和晨光从左侧窗户进入，在桌面和地板投出同向亮区，呈现深褐木纹、灰白墙面与青瓷各自的材质。
```

## 多参考与局部修改

合成时写明「从某张图提取什么对象 → 放到目标图什么位置」，并说明相对尺度、接触阴影与原有透视。已有基底接近目标时，用简短修改指令只改变化项，明确保留的不变量；画内含复杂文字时，先核准精确文案再写入。

下面假设人物图和上述空场图均已传入；正式使用时在引用位置按规范插入真实 `<ref input_id="…" label="…" />`：

```text
以人物图保持同一人的面貌、发型与深蓝长衫，不继承其原本背景与站姿；以茶馆空场图保持门窗、柜台、桌凳与通道位置。
人物坐在左窗方桌靠墙一侧，双手放在桌面，视线朝向画外入口。入口方向中景容纳头身、双手与桌沿；晨光仍从左窗进入，人物与桌凳尺度协调并在座面与桌面落出接触阴影。
```

局部微调（如改长衫颜色）时，只声明色相变化并列出保持项（脸、衣型结构、坐姿、视线、光位）；多图重点检查是否错位借图或把参考拼板直接复制进成图。

## 能力边界

普通图像请求未开启联网检索时，不能假定生成前会查询真实地标，需要写实参照时需自行提供参考或具体视觉特征。
