# 视频生成提示词

## 写作原则

正文围绕“主体与场景 → 起始构图 → 动作过程 → 运镜 → 声音 → 结束状态”展开，写本段实际需要的内容。人物和关键道具使用稳定称呼；真实参考已经交代的外观不反复改写，跨段必须保持的特征则明确保留。整体风格落实到光源方向、色温、质感与运动方式，少用无具体含义的“高级、电影感、史诗级”等堆叠。

对白保留原话、说话人和口语语言，注明语气、语速与发声窗口；不要翻译台词来迁就提示词语言。环境声、音效、音乐各写实际需要的一层，不擅自加旁白、台词或字幕。剧本或用户要求画面文字时，写清准确文本与承载位置，区分画内招牌和后期字幕。提示词语言沿用用户要求或已有正文，不随界面语言改变；所选模型的格式附件规定了提示词语言时，以该附件为准。

声音跨切镜时说明延续或停止。同一句对白跨镜继续时划清发声区间，不在每个 Shot 重写整句造成重说；动作同步声、持续环境底声和画外配乐分别交代。声音描述也会驱动画面：写了“铃铛被撞响”，模型会倾向演出撞击，所以改动作时同步删改对应声音。音频参考只借节奏或气氛时说明范围，不默认复刻其中人声。

提示词是生成意图，不是效果保证。把不确定的素材、配置和后期待办留在交付说明中，不混入 prompt；不要加入工具调用、Read 路径、素材本地路径、内部检查记录或未替换占位符。

镜头整体设计见 [分镜指南](storyboard.md)；组织具体提示词、查运镜对照表与完整案例时读 [镜头任务配方](shot-recipes.md)。已有设计直接沿用，按本附件选择输出格式与模型写法。

## 按模型选择格式

不同视频模型按各自官方规范解析提示词，结构、时间写法、台词与声音标记都不同，写错格式会直接影响效果。同一型号在不同渠道的 model_id 写法不同（如 `bytedance/seedance-2.0`、`minimax/h3`、`google/veo3.1`），不按 model_id 字面匹配。按「模型能力」附件查询分镜所选渠道的模型列表，找到 `id` 等于分镜 model_id 的条目，用它的 `catalog_model_id` 选格式：

| catalog_model_id | 格式附件 |
|---|---|
| `doubao-seedance-2-0-260128`、`doubao-seedance-2-0-fast-260128`、`doubao-seedance-2-0-mini-260615`、`seedance-2.0-fast` | [Seedance 提示词](seedance-prompts.md) 的 2.0 写法 |
| `doubao-seedance-2-5-260628` | [Seedance 提示词](seedance-prompts.md) 的 2.5 写法 |
| `MiniMax-H3`、`minimax-h3-fast`、`minimax-h3-max-turbo`、`hailuo-3-max` | [MiniMax H3 提示词](minimax-h3-prompts.md) |
| `kling-v3.0-pro`、`kling-v3.0-std`、`kling-video-o1`、`kwaivgi-kling-v3.0-4k`、`kwaivgi-kling-v3.0-turbo` | [Kling 提示词](kling-prompts.md) |
| `veo-3.1`、`veo-3.1-fast`、`veo-3.1-lite` | [Veo 提示词](veo-prompts.md) |
| `wan3.0-video`、`wan3.0-video-prime`、`wan-2.7`、`wan-2.6` | [通义万相提示词](wan-prompts.md) |

有专属附件的模型按附件写：其结构、时间写法、标记和提示词语言取代本附件的通用格式与语言约定，内容原则（原文覆盖、动作过程、声音分层、参考用途）仍照本附件和分镜指南执行；逐字台词始终保留原语言。`catalog_model_id` 为 null 或不在表中（包括同品牌的其他版本，如 `kwaivgi-kling-v4.0`、`alibaba-wan-2.5`、`hailuo-2.3`）、模型尚未选定，或用户明确要求通用格式时，使用下方通用格式，不套用相近型号的专用语法。更换模型后按新模型的格式重写整条提示词，不在旧格式上局部替换。

所有格式中，素材引用一律使用应用的 ref 标签。提交时应用会按渠道把标签换成该供应商的图片编号，所以不手写 `@图片1`、`<Picture 1>` 这类编号；专属格式要求在某处提到某张参考时，在那个位置放对应的 ref 标签。

## 通用镜头格式

一次生成的视频可以包含一个或多个镜头。按镜头逐个描述，每个镜头依次写：

- 镜头头：`Shot N（景别·角度·运镜·时长）`，例如 `Shot 3（近景·微俯拍·手持固定构图·2s）`。
- 区间：`【起-止s】`，表示该镜头在本次生成视频中的起止时间。镜头按顺序首尾相接，从 0 开始，最后一个镜头的结束时间等于生成时长。
- 首帧：开场画面的景别、构图、前景与背景、人物位置和姿态、光线。
- 节拍：每行以 `[起-止s]` 开头，写这段时间内可见的动作、表情、视线、镜头运动，以及对白原话和语气、语速。时间码落在本镜头区间内，按时间顺序排列，可以精确到 0.1 秒。
- 结束状态：本镜头最后一帧的画面，供下一个镜头或下一次生成衔接。

没有首帧图、只靠文字或身份参考生成时，首帧行要承担构图图片原本提供的信息，否则景别容易偏远、动作偏小、站位随意。按需补齐：焦段与景深（如“50mm 标准焦段，中浅景深”）、机位对着谁及角度、构图方式、人物视线落点、对焦主体，以及固定、微晃或手持的机身状态；视线落点和对焦主体可以不同，例如眼睛看对方、焦点落在手里的刀。多人片段在 Shot 1 首帧写一次开场站位：谁在画面左右、各自朝向、相距几步，后续 Shot 从这个空间出发。已有首帧图时只写图中看不出的部分，不与图片矛盾。

只写画面中看得见、听得见的内容，不写心理活动或剧情解释。调整某个镜头的时长后，同步修改其后各镜头的区间和节拍时间码，并核对总时长与生成配置一致。用户只要求改某个镜头时，只改对应段落，其余镜头原样保留。

上述 Shot 格式在本附件维护，用于界面一条分镜的提示词；不要把每个 Shot 都新建成分镜。时间码用于表达节奏，模型未必精确执行每个切点。实际写入遵循「工具技能」的分镜与媒体节点附件。

对白反打、交接、遮挡揭示和续拍的完整成稿见 [镜头任务配方](shot-recipes.md)；多段如何覆盖整场原文见 [整场制作案例](scene-example.md)。不要只输出本节格式骨架代替用户要的实际提示词。

## 三镜头片段示例

假设原文为“林岚将钥匙推到桌沿。周明没有接，只问：‘你真的要走？’林岚松开手。”，目标为无参考的 8 秒片段，duration_ms 为 8000。以下只示范提示词正文，不代表已配置模型或已生成视频：

```text
Shot 1（中景·平视·固定·4s）
【0-4s】
首帧：夜间室内，暖色台灯从画面左侧照亮木桌。林岚在画面左侧，周明坐在右侧，两人隔桌相对。林岚右手按着桌上的一把钥匙，周明双手停在自己一侧桌沿。
[0-2s] 林岚用右手食指把钥匙沿桌面推向周明，在桌沿内侧停住，指尖仍压着钥匙。
[2-4s] 周明看着钥匙，没有伸手，随后抬眼看向林岚。房间安静，只听见钥匙擦过桌面的声音。
结束状态：钥匙留在周明面前的桌沿内侧，林岚指尖仍按着它；周明抬头，双手位置不变。

Shot 2（近景·平视·固定·2.5s）
【4-6.5s】
首帧：切到周明近景，沿用上一镜人物轴线和左侧暖光，周明看向画面左侧的林岚。
[4-6.5s] 周明保持视线，压低声音用普通话问：“你真的要走？”语速放缓，句末稍停。
结束状态：周明说完后仍看着林岚，等她回应，没有伸手拿钥匙。

Shot 3（特写·微俯拍·固定·1.5s）
【6.5-8s】
首帧：切到桌沿钥匙特写，沿用左侧暖光。林岚右手食指仍压着钥匙，手从画面左侧伸入。
[6.5-8s] 林岚的右手食指松开并退向画面左侧，钥匙留在原处。对白结束后只保留室内底声。
结束状态：钥匙独自留在周明一侧桌沿内侧，没有被拿起。
```

## 结合真实参考写作

修改提示词时按「工具技能」的分镜与媒体节点附件保护已有素材引用。只改镜头表达时保留标签及语义；用户要求更换参考时，先按该操作契约完成输入与提示词的一致修改。

围绕实际可核对的参考安排主体、构图、动作与结束状态，不根据显示名称猜图片或视频内容。缺少素材时先写可用草稿，把素材缺口放在交付说明中，不将未绑定的参考描述为已提供。

说明参考允许继承的范围：人物图管身份，实际上一段尾部管当前站位与持物，动作参考可只借动作或机位，不自动带入其中的服装、背景和原声。多主体参考要明确目标；参考互相矛盾时先确定本场状态与各自用途，不用“全部保持一致”掩盖冲突。需要准备或修正图片时读取本技能的图片资产与参考附件，引用仍使用应用已有标签。
