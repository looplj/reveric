# 模型能力与配置

## 先确认执行条件

通过「系统管理」的媒体渠道与模型查询附件，使用 Run providers 读取真实 provider_id、model_id、能力和默认配置；视频模型同时记下 `catalog_model_id`，供选择提示词格式。优先沿用分镜已选型号；能力未知或不可用时说明原因，不根据品牌或相似型号猜限制。配置可用不代表远程权限、额度和网络已验证。

按会影响本次制作的条件核对：

| 条件 | 对分镜与提示词的影响 |
|---|---|
| 确切型号与渠道 | 不把 mini、不同版本或相似名称当成同一能力，也不自行替换用户指定模型 |
| 单次时长 | 决定一次生成装多少镜头；镜头内节拍可以细到 0.1 秒，字段单位与取整要求见「工具技能」 |
| 画幅与分辨率 | 先确定构图再安排人物与动作；字段使用所选模型接受的精确值，写“4K 画质”不能改变实际输出参数 |
| 输入模式与参考用途 | 区分无参考、首帧、首尾帧和全参考；人物身份参考不等于固定首帧，视频参考不自动等于原生延长功能 |
| 素材数量与规格 | 核对类型、数量、尺寸、文件大小、视频／音频时长等；不要把所有素材都塞进每段，缺失或超限时先调整输入或说明缺口 |
| 声音与口型 | 区分音频参考、生成音轨和逐字口型控制；支持其中一项不保证其他项，不能承诺精确复现 |
| 提示词长度与可控程度 | 优先保留动作因果、连续性和对白；删掉重复修饰，不以堆砌术语代替可见行为，也不把时间码当成逐帧执行保证 |

## 用实际能力安排制作

以本次查询返回的时长集合、画幅、分辨率、输入模式、媒体数量与规格限制安排镜头；参数原样使用，保留大小写。不同渠道的同名模型也可能有不同限制。更换模型、参考方式或实际输入后，重新核对配置与提示词总时长，不沿用另一型号的参数表。

模型能力决定可提交范围，不决定每段必须填满多长时间，也不保证精确切镜、口型或角色一致性。没有已确认模型时可先写草稿并标明暂定时长，不能声称配置已经验证。

## 将同一镜头改写到不同输入方式

时长、画幅、素材数量等参数以运行时查询为准，不按模型名字背数字；提示词格式按「视频提示词」附件的模型对照选择专属规范。先区分本次输入实际提供了什么，再决定哪些信息必须由文字补足。同一任务的改写可以按以下方式比较：

| 任务条件 | 提示词怎样变化 | 不能偷换的条件 |
|---|---|---|
| 纯文本生成 | 独立建立主体外观、场景布局、开场动作和光线，不写“照图” | 外观缺失应先列草稿假设，不虚构已提供角色图 |
| 已有首帧 | 从图中真实姿态与持物开始，重点写接下来的运动、声音和终点 | 不让首帧已经坐下的人重新从站立开始坐下 |
| 首尾帧 | 两端分别代表起止状态，文字负责必需过程与速度变化 | 两端身份、场景结构或状态有矛盾时先修输入 |
| 多参考输入 | 分开身份、状态、空间、构图与风格，删除已由参考说明的重复外观 | 不把身份图姿势强加给分镜，不把全套素材都无差别送入 |
| 参考视频／导演预演 | 说明借用路线、机位或节奏的哪一部分，再补真实造型和表演 | 动作参考不自动继承人物、服装与原声；预演也不是已生成的成片 |
| 已有片段续拍 | 从实际尾部状态继续；区分重新生成下一段和渠道真正支持的延长操作 | 不因工具接受视频输入就声称能原生延长 |

例如同一“站在门外的人推门入室”：无参考时需交代人物与门的位置、门的开启方向；首帧版只写图中那只手怎样压下把手、门怎样打开；动作参考版先说明只借推门和入室路线，外貌及门的结构仍依本剧。若实际首帧里门已全开，不能沿用“压把手开门”的草稿；应改输入或承接已经完成的动作。

模型切换时按需求重新适配：

- 单次时长变短：在完整动作阶段或语义边界拆开，分别重置每段时间码并写独立起点；不要把整段等比加速。
- 可用参考变少：按本镜最难保持的身份、空间或物件选择必要输入；需要先合成首帧时检查其准确性和输入支持，不默认以拼图绕过数量限制。
- 不支持要求的声音／口型：保留逐字台词和发声计划，明确哪些需配音或剪辑；不能把新增音轨写成模型已经具备的能力。
- 不支持长提示词或复杂切镜：先删重复外观和空泛修饰，再降低同次动作负载；不删掉决定剧情的动作、说话人和终点。
- 画幅改变：重新检查主体、互动距离和证据文字能否读清，不只替换提示词里的比例数字。

交付时简记“实际型号与输入方式、采用的时长／画幅、引用用途、尚未验证的控制”。这是本次制作记录，不是新增一套必填字段或长期模型参数表。

## 参考方式与写法

先按「工具技能」确认实际输入与参考方式。界面“全参考”与“首尾帧”的配置和输入必须一致；有参考计划不等于已经绑定。

| 实际输入 | 提示词重点 |
|---|---|
| 无参考 | 完整交代主体、外观、场景、构图、光线与动作，不能只写“保持原样” |
| 首帧 | 从已有画面出发写动作、镜头变化和终点；不重新设计已确定的外观与起始构图 |
| 首尾帧 | 写起点如何可信地到达终点，保持中间过程和身份一致；不把互不相容的两帧硬写成自然过渡 |
| 全参考 | 说明每个已知参考负责的内容，如人物外观、场景、动作节奏或声音；不用同一个参考同时承担相互冲突的要求 |

原生首尾帧用于约束两端画面，但也不保证中间关键动作出现。仍须写清动作顺序与必须看见的过程；例如剧情要求看清钥匙交到谁手里，不能只提供“甲拿着”和“乙拿着”两张图就认为交接已表达。过程本身承担戏剧信息时，安排独立可见的动作镜头或拆段，生成后核对，不把所有首尾帧任务都当成状态渐变。

输入模式切换后重新核对实际模型接受的画幅与规格，特别是 adaptive 是否适用于本次输入。不要把一个型号的要求推广到其他型号。

未选模型时可按叙事节奏写草案并说明暂定时长，保留模型配置为空；不把猜测的限制说成已验证。没有专属格式附件的模型不套用其他模型的专用语法；未知的原生编辑、延长或声音控制，也不因型号相近就推定支持。模型效果没有通用优劣排名；按当前镜头的身份保持、动作、对白或构图要求判断，生成效果需看实际结果。

## 原生边界与普通参考的区别

按真实型号与渠道确认原生首帧／首尾帧，而不是只看界面用途标签。首尾帧组与全参考组在提交时实际发送哪些输入、以什么角色发送，按「工具技能」的分镜与媒体节点附件核对；全参考组里的首尾帧只是普通参考加文字约束，不能承诺与原生首尾帧相同的边界一致性。

需要身份、场景、道具和边界构图共同成立时，先按 [图片资产与参考](image-references.md) 合成并核对一张干净的正式关键帧，再交给支持原生帧约束的视频型号。不要为了通过校验静默丢弃用户期待保留的参考，也不要要求接口同时接收互斥的两组输入。完整动作的生成边界先按 [制片流程](production.md) 决定；原生模式本身仍需验收中间动作、身份和真实接缝。
