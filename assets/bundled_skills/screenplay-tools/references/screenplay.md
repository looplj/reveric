# 剧本结构与正文操作

## 定位与读取

- 先确定目标季、集，再定位任务涉及的场次。已有明确目标路径时直接读取，不为一次局部操作遍历全剧。
- 集大纲与场次梗概用于理解结构；核对或修改正文时，读取相关场次的正文元素及所需人物信息。不要把梗概当成已经写入的正文。

## 新建结构与正文

- 复用已有季和集，只补齐任务需要的结构。新建季会同时返回首集，先使用返回的首集路径，避免重复创建；只有用户要求新增季时才建季。
- 场次引用的人物与地点先定位到真实资源；缺少依赖时，先补齐获准创建的条目，再写入引用它们的场次或正文元素。
- 规划结果写入对应集大纲或场次梗概；正文写入场次的结构化元素。只要求规划时不生成正文，也不用写梗概代替写场。场景标题写进场次字段，不写进正文。不得把整场正文或整段 Markdown 塞进一个动作元素。
- 人物提示后的连续元素可包含 `parenthetical` 和一个或多个 `dialogue`。`parenthetical` 表示该角色的简短表演、反应或语气提示，如“低声”“停顿”“看向窗外”；可以单独表示无台词反应，也可以放在对白前修饰说话方式。它不得包含角色实际说出的内容，也不得复述相邻的 `dialogue`，文本中不要自行加括号。比如“萧炎低声说：我会回来。”应写为 `character=萧炎`、`parenthetical=低声`、`dialogue=我会回来。`，不能把“（低声）我会回来。”同时写进 `parenthetical` 和 `dialogue`。
- `parenthetical` 只承载紧贴该角色提示的短表演或反应；需要独立呈现的画面、环境变化、多人动作或较完整的行动过程使用 `action`。例如“把玉瓶收进怀里后走到窗前”应作为 `action`，而角色听到消息后的“沉默片刻”可以是 `parenthetical`。

## 修改已有内容

- 先读待改内容，按改动范围选择操作：文本局部替换用 Edit，字段更新用 Write，增删条目用 Create / Remove。改一句台词就只改对应元素，不重发整场正文。
- 整场重写或元素重排需要整体提交元素数组时，先读齐现有元素，保留未改内容及已有元素 ID；分页尚未读完时不得用局部结果覆盖完整数组。
- 移动或删除正文元素前，检查受影响的完整对白块，确保人物提示与后续台词仍符合元素契约。调整场次位置或归属后，重新核对所属集和相邻顺序。

## 写后核对与事实整理

- 核对本次实际写入的范围；改动影响集大纲或场次梗概时，在用户授权范围内同步相关内容，避免规划与正文脱节。
- 正文返工后，列明变更场次与受影响事实，供写后整理核对。事实整理的执行者与触发条件遵循主 Agent 的剧本工作区指引，提取方法由「故事连续性维护」提供。
- 仅调整名称、排序等结构信息时，不重新提取正文事实；修改梗概也不能冒充已更新故事状态。
